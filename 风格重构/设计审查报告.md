## 一、适用范围裁定（先读两个 skill 的边界声明）

**taste-skill 自我声明 OUT OF SCOPE**（§13）："Not for: Dashboards / dense product UI / admin panels、Data tables、Multi-step forms、Code editors、Native mobile、Realtime collab UIs." 并要求：**遇到这类 brief 必须明说**，只借用其通用部分。

本项目是 ERP（11 个列表页 + 4 个表单页 + 3 个详情页 + 仪表盘 + 移动端 16 页），**正中其排除清单**。因此：

| 工具 | 对本项目的适用裁定 |
|---|---|
| taste-skill 页面级规则（hero/bento/logo wall/marquee/eyebrow/文案密度） | ❌ 不适用，不引入 |
| taste-skill 横切标准（排版纪律、色彩校准、图标策略、动效守则、a11y、AI Tells、Pre-Flight 对比度检查） | ✅ 适用，全部采纳 |
| redesign-skill（Scan → Diagnose → Fix，审计已有项目、按现有技术栈小步修复） | ✅ 完全适用，作为主审查框架 |
| 官方设计系统建议（§2.A："enterprise SaaS / dashboards → 用官方系统，别手搓 CSS；不要导入系统令牌又覆盖 90%"） | ⚠️ 对应到本项目 = **Element Plus 就是我们的官方系统**：主题必须走 EP 变量 API，组件不手搓、类覆盖最小化并有据可查 |

**目标站性质再确认**：fuu9qs9u.qwenwork.host 是一个"展示型 demo"——低信息密度、营销化的宽间距（页边距 26-28px、卡片内距 20px、KPI 数字 30px）。**它是给人看气质的，不是给人干活的**。直接照搬密度到 ERP 会降低信息效率，这是本次审查最重要的发现（见 P0-1）。

## 二、Design Read 与三档参数（taste-skill §0/§1 强制输出）

> **Reading this as: 企业内部 ERP 多页数据密集产品界面，受众是 salesman/tracker/finance/admin 四类业务角色，vibe 是「克制的现代产品感」，redesign-overhaul 模式（保留 IA 与内容，视觉语言整体换新）。**

按 skill 的换算表（redesign-overhaul = 现有值 +2 variance / +2 motion / 密度保持不变）：

| 参数 | 取值 | 依据 |
|---|---|---|
| `DESIGN_VARIANCE` | **3-4** | ERP 要可预期、可肌肉记忆；目标站的 1.6fr:1fr 非对称网格只在仪表盘使用，**表格/表单区禁止非对称** |
| `MOTION_INTENSITY` | **3-4** | 功能性微交互（hover/active/入场），不做滚动编排、不做无限循环动画；必须支持 `prefers-reduced-motion` |
| `VISUAL_DENSITY` | **7** | 数据密集。目标站实测约 3-4，**必须做密度适配，不得照抄** |

## 三、审查发现

### P0（开工前必须修订规格）

**P0-1 · 密度照搬风险（最重要）**
规格把目标站的间距当"照抄"对象。但 taste-skill §7 定义 `VISUAL_DENSITY 7-10 = Cockpit`：紧凑内距、少卡片、数字用等宽。需在规格中新增「密度适配表」：
- 保留：目标站的**表格密度本身已够紧**（`.tb` 行 padding 9px 12px / 字号 12px），可原样采用
- 收紧：页级内距 26-28px → 20-24px；卡片内距 20px → 16px
- 重排：KPI 从"3 张 30px 大数字卡"改为 **4-6 列紧凑指标行**（数字 22-24px）

**P0-2 · 仪表盘"三张等高卡片"违反 AI-Tell**
taste-skill §4.4：`VISUAL_DENSITY > 7` 时**通用卡片容器被禁**，指标应"平铺 + 细分隔线呼吸"；§9.C 亦禁"三列等高卡片"。仪表盘 KPI 区改为无卡指标行 + 1px 分隔线，不做三张一模一样的卡。

**P0-3 · 图标方案双重违规，改用 Phosphor**
规格 §3 写"引入 lucide-vue-next 或自建 11 个内联 SVG"，命中两条硬禁令：
- taste-skill §3.C/§9.E："**NEVER hand-roll SVG icons**，不要从零画图标路径"
- redesign-skill Iconography："**Lucide 是默认 AI 选择**，改用 Phosphor / Heroicons / 自定义套件"

修订：**PC 端统一用 Phosphor Icons**（`@phosphor-icons/vue`，单一家族、全局统一 strokeWeight、weight 变体天然区分导航=regular / 按钮=bold）。移动端 Vant 图标保留（Vant 是移动端官方系统的一部分），仅统一尺寸与色。目标站那 11 个自绘 SVG **不作为移植对象**，只借鉴"细描边几何风"这一风格属性。

**P0-4 · 浅色主题两个硬约束（规格里的深色数值不可直接搬）**
- taste-skill §8.B/§9.A：**禁止纯 `#FFFFFF`、禁止纯黑阴影**。浅色版面板用 off-white（如 `#FCFCFD` 系列，画布 `#F2F3F5` 一带），**阴影必须带底色调**（如 `rgba(23,26,20,.06)` 微绿灰），不得使用 `rgba(0,0,0,.x)`
- 规格 §1.5 里抄的目标站黑色阴影（`0 30px 80px rgba(0,0,0,.5)` 等）**只适用于深色主题**，浅色版全部重算

**P0-5 · 动效缺两个强制项**
- taste-skill §6.B 强制：`MOTION_INTENSITY > 3` 必须尊重 `prefers-reduced-motion`（无限循环/视差/滚动劫持在 reduced 下降级为静态）
- §4.5 强制：**可见的 focus ring**（键盘可达性），且按钮/表单的对比度必须过 WCAG AA（4.5:1 正文 / 3:1 大字）
- 规格 §7 两者均缺失，需补

**P0-6 · 导航 IA 变更必须显式设计**
redesign-skill §11.C："不得静默改信息架构；页面 slug、锚点、**一级导航标签保持不变**"。三面板壳已获批准，但"220px 分组菜单 → 76px 图标栏"必须保标签与顺序不变：
- 图标栏 = 现有 7 个一级分组（基础信息/订单管理/跟单管理/工厂结算/物流管理/轻财务/系统管理）
- 分组项 hover/点击 → 弹出 flyout 面板展示组内页面（标签、顺序、路由全部原样保留）
- 登录后默认落地页、路由结构零改动

### P1（应当修订）

**P1-1 · 执行顺序调整（两个 skill 的修复优先级高度一致）**
taste-skill §11.D 与 redesign-skill Fix Priority 都给出同一顺序：**字体 → 色彩 → 交互状态 → 布局间距 → 组件替换 → 状态完善 → 抛光**，且 redesign-skill Rules 明确"小步、可审查、**避免大重写**"。
规格 §10 的 M1-M6 把最大的结构变更（壳层）放在第 2 步，风险过早。建议改为：
1. **M1 令牌 + 排版**（含浅色阴影重算、EP/Vant 变量映射）— 最低风险最高收益
2. **M2 组件层**（表格/按钮/表单/分页调校 + 公共组件抽取 + loading/empty/error 三态）
3. **M3 壳层**（三面板 + 图标栏 flyout + 顶栏 + 登录页）
4. **M4 图表与业务页面铺开**（Dashboard 6 图 + 11 列表页 + 详情/表单页）
5. **M5 移动端**（Vant 变量 + banner + tabbar）
6. **M6 扫尾**（硬编码色值全扫描、favicon、404、skip-link、reduced-motion 走查）

**P1-2 · 蓝色降级为纯语义色**
taste-skill §4.2"一页一强调色" + Color Consistency Lock：lime 是唯一强调色。目标站里蓝（#3355FF）还兼任 P1 优先级、甘特条、日历点等**装饰性角色**——浅色版应收敛：蓝只保留 info 语义（提示条），P1 优先级改用中性灰阶表示，不新增蓝色装饰用途。

**P1-3 · 状态三件套写进规格**
redesign-skill Interactivity：骨架屏替代圆形 spinner、组合式空状态（含引导 CTA）、内联错误。规格需明确：列表 loading 用骨架行（EP `el-skeleton`）或保留 spinner——**二选一写死**；空状态从裸 `el-empty` 升级为"说明 + 主操作按钮"组合。

**P1-4 · 字体策略修订**
- taste-skill §4.1 劝退 Inter 作默认；中文界面里拉丁字体影响面小，**数字才是重点**
- 修订：CJK 用 `PingFang SC`/系统栈；数字全局 `tabular-nums`（已规划 ✓）；可选给数据数字加半等宽字体（如 IBM Plex Mono / Geist Mono）仅用于金额、数量、日期场景
- 中文行高从目标站的 1.55 提到 **1.6-1.7**（中文可读性）

**P1-5 · 卡片收敛**
redesign-skill Component Patterns："通用卡片（边框+阴影+白底）只在真实层级需要时使用"。目标站"万物皆卡片"，ERP 高密度下需收敛：页面内的搜索工具栏、表格容器、表单区**不重复套卡片**；嵌套卡片最多两层。

### P2（可选/加分项，扫尾批次处理）

- 语义状态点克制使用（taste-skill §9.F：装饰性彩点默认禁止，只保留真实语义，如跟单 8 节点状态）
- 进度条（成员负载/项目进度）只用于真实数据，考虑"无轨道细条"变体（§9.F 对带底轨的进度条有警告，产品界面可豁免但需克制）
- `100vh` → `100dvh`；标题加 `text-wrap: balance` 防孤字；建立 z-index 规范表
- 404 页、skip-to-content 链接、头像用圆角方形（squircle）替代纯圆形做差异化

## 五、结论

**规格的整体方法论成立**（令牌化、组件化、分批交付、对照目标站取值），且经得起两个 skill 的横切标准检验；但**密度、图标、浅色阴影、动效可达性、导航 IA 五个 P0 项必须先在规格中修订**，否则开工即埋返工。

两个 skill 给本项目的核心证词是一致的：**ERP 类界面不吃 landing page 的设计技巧，"高级感"不来自视觉花活，而来自排版纪律 + 密度控制 + 状态完备**。这正好和我们的方向吻合：目标站值得学的是它的**层次系统与克制度**，而不是它的低密度与展示性元素。
