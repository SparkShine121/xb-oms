## 3. 数据模型

### 3.1 TrackingLog（`apps/tracking/models.py`）

| 字段 | 类型 | 说明 |
|---|---|---|
| order | FK→Order, on_delete=CASCADE, related_name='tracking_logs' | 所属订单 |
| node | CharField（choices 9 节点） | 本次流转目标节点（advance 下一/ reject 上一） |
| note | TextField, blank | 跟进文字 |
| operator | FK→User, on_delete=SET_NULL, null | 操作人 |
| is_reject | BooleanField default False | 推进 False / 驳回 True |
| created_at | DateTimeField auto_now_add | 时间戳 |

### 3.2 TrackingPhoto（多张）

| 字段 | 类型 | 说明 |
|---|---|---|
| tracking_log | FK→TrackingLog, on_delete=CASCADE, related_name='photos' | 所属记录 |
| image | ImageField(upload_to='tracking/%Y%m/') | 照片（按年月分目录） |
| created_at | DateTimeField auto_now_add | 时间戳 |

### 3.3 Order.tracking_status（第二模块已建）

流转时更新为 TrackingLog.node（当前节点）。is_cancelled 订单不进流转。

### 3.4 状态机（`apps/tracking/state_machine.py`）

```python
TRACKING_FLOW = ['接单','排产','生产中','质检','发货','签收','结算','回款']
def next_node(node): ...  # 下一节点或 None（回款终态）
def prev_node(node): ...  # 上一节点或 None（接单无）
```

### 3.5 MEDIA 配置

`base.py`：`MEDIA_ROOT = BASE_DIR / 'media'`，`MEDIA_URL = '/media/'`。
`dev.py` urls 加 `static(settings.MEDIA_URL, document_root=settings.MEDIA_ROOT)`。`.gitignore` 加 `media/`。requirements 加 `Pillow`。

### 3.6 照片限制

单张 <5MB、jpg/png/jpeg、每条 TrackingLog 最多 9 张。

## 4. 状态机 + API

### 4.1 API（前缀 `/api/tracking/`）

| 端点 | 方法 | 说明 |
|---|---|---|
| `/tracking/orders/{id}/advance/` | POST | 推进：note + photos[]（multipart）→ TrackingLog（is_reject=False）+ Order.tracking_status=下一节点 |
| `/tracking/orders/{id}/reject/` | POST | 驳回：note + photos[] → TrackingLog（is_reject=True）+ Order.tracking_status=上一节点 |
| `/tracking/orders/{id}/timeline/` | GET | 跟单时间线：TrackingLog 倒序 + 嵌套 photos |
| `/tracking/my/` | GET | 工作台：派给自己的订单 + tracking_status + 停留时长 |

### 4.2 advance/reject 流程

```
取 Order（按权限过滤 get_queryset）
  → 校验：is_cancelled 不可流转；回款不可 advance（next=None）；接单不可 reject（prev=None）
  → node = next_node/prev_node(order.tracking_status)
  → 创建 TrackingLog（order + node + note + operator=request.user + is_reject）
  → 处理 photos[]：上传 → TrackingPhoto（最多 9 张，校验大小/格式）
  → 更新 Order.tracking_status = node
  → 返回 TrackingLogSerializer + 新 tracking_status
```

### 4.3 timeline

`TrackingLog.objects.filter(order=order).order_by('-created_at')`，serializer 嵌套 photos。

### 4.4 my（工作台）

`tracker=request.user, is_cancelled=False`，返回 order_no/customer_name/tracking_status/停留时长（当前节点最早 TrackingLog.created_at 距今）+ 可推进/驳回标志。

### 4.5 照片上传

multipart：note（文字）+ photos[]（`request.FILES.getlist('photos')`）。校验大小/格式/数量。

## 5. 权限

### 5.1 权限矩阵

| 操作 | admin | salesman | tracker | finance |
|---|---|---|---|---|
| 查看订单 + 时间线（含推进/驳回记录） | 全部 | 自己客户 | 派给自己 | 全部（只读） |
| 推进/驳回（advance/reject） | 全部 | — | 派给自己 | — |
| 派单（第二模块已实现） | ✓ | — | — | — |

### 5.2 实现（`apps/tracking/permissions.py`）

**TrackingPermission**：
- has_permission：advance/reject 要求 admin 或 tracker；timeline/my 要求 IsAuthenticated
- has_object_permission（advance/reject/timeline 按 order pk）：admin 全部；finance 全部只读；salesman order.customer.salesman=自己（只读）；tracker order.tracker=自己

### 5.3 get_queryset（按角色过滤 Order）

复用第二模块 OrderViewSet 过滤：admin/finance 全部、salesman customer__salesman、tracker tracker、Q 并集。`my` 固定 tracker=request.user。

### 5.4 与第二模块权限关系

OrderPermission 管 Order CRUD；TrackingPermission 管跟单流转。独立，按操作类型分别校验；数据范围过滤逻辑一致。

## 9. 风险与备注

| 风险 | 应对 |
|---|---|
| 照片上传在 ARM 平板较慢 | 限制 5MB/9 张；前端压缩可选 |
| 状态机非法跳转 | 目标节点后端自动算（客户端不传），校验边界 |
| 跨 app FK（TrackingLog→Order） | Django 成熟支持，字段变化无影响（FK 只依赖主键） |
| 媒体文件部署 | 生产由 Nginx serving /media/，开发 Django static |
| 移动端拍照兼容性 | vant-uploader capture 属性，兼容主流浏览器 |
