## 1. 模块范围

本模块是系统第一个开发模块，交付**可运行可访问的项目骨架**与**基础信息域**的全部功能，为后续 8 个业务模块提供工程基础与主数据。

**包含**：
- 工程骨架：Django+DRF 后端、Vue3 前端、MySQL、用户登录、角色权限、前端主布局
- 基础信息 6 张表：类目、产品库、工厂库、物流服务商、客户、客户-业务员对照（并入 Customer）
- 产品库、工厂库的 Excel 批量导入
- 移动端骨架：登录 + 首页 + 基础信息只读浏览

**不包含**：订单导入、跟单、工厂结算、物流账单、轻财务、数据分析、数据可见范围（留到订单模块）。

### 完成定义（DoD）

1. 后端 6 张表 + API + 认证权限 + 批量导入，pytest 全绿；
2. 前端 PC 端 6 个管理页 + 用户管理 + 登录 + 主布局，vitest 全绿；
3. 移动端登录 + 首页 + 基础信息只读浏览可运行；
4. 本地可运行（`runserver` + `vite dev`），能登录、增删改查基础数据、批量导入；
5. 模块完成后调用 neat-freak 整理。

## 3. 数据模型

6 张表。所有表含 `created_at`、`updated_at`（auto）。金额用 `DecimalField`。

### 3.1 Category 类目

| 字段 | 类型 | 说明 |
|---|---|---|
| id | AutoField PK | |
| name | CharField | 类目名 |
| parent | FK→Category, null | 自关联，两级（顶层 parent=null） |
| sort_order | IntegerField, default=0 | 排序 |

### 3.2 Product 产品库

| 字段 | 类型 | 说明 |
|---|---|---|
| id | AutoField PK | |
| product_no | CharField, unique | 产品编号（唯一标识） |
| model | CharField | 型号 |
| name | CharField | 产品名称 |
| category | FK→Category, null | 所属类目 |
| spec | TextField | 规格（自由文本） |
| default_price | DecimalField(USD) | 默认单价 |
| default_cost_price | DecimalField(CNY) | 默认含税成本价 |
| remark | TextField, blank | 备注 |

### 3.3 Factory 工厂库

| 字段 | 类型 | 说明 |
|---|---|---|
| id | AutoField PK | |
| name | CharField, unique | 工厂名 |
| alias | CharField, blank | 别名（映射"外部YT/外部XM"等） |
| contact | CharField, blank | 联系人 |
| phone | CharField, blank | 联系方式 |
| settle_currency | CharField, default='CNY' | 结算币种 |
| remark | TextField, blank | 备注 |

### 3.4 LogisticsProvider 物流服务商

| 字段 | 类型 | 说明 |
|---|---|---|
| id | AutoField PK | |
| name | CharField | 服务商名 |
| type | CharField(choices: domestic/international) | 国内/国际 |
| contact | CharField, blank | 联系人 |
| phone | CharField, blank | 联系方式 |
| remark | TextField, blank | 备注 |

### 3.5 Customer 客户

| 字段 | 类型 | 说明 |
|---|---|---|
| id | AutoField PK | |
| name | CharField | 客户名 |
| contact_person | CharField, blank | 联系人 |
| phone | CharField, blank | 电话 |
| email | CharField, blank | 邮箱 |
| salesman | FK→User, null | 归属业务员（即客户-业务员对照） |
| remark | TextField, blank | 备注 |

### 3.6 客户-业务员对照

**不单独建表**。归属关系由 `Customer.salesman` 字段承载；"按业务员筛选客户"通过 `GET /customers/?salesman=` 实现。订单导入时按客户名查 Customer.salesman 决定订单归属。若未来需"一客户多业务员"再改多对多。

## 4. API 设计

DRF ViewSet + Router，统一前缀 `/api/`。

| 资源 | 标准端点 | 特殊端点 |
|---|---|---|
| Category | CRUD | `GET /categories/tree/` |
| Product | CRUD | `POST /products/import/`、`GET /products/import-template/` |
| Factory | CRUD | `POST /factories/import/`、`GET /factories/import-template/` |
| LogisticsProvider | CRUD | — |
| Customer | CRUD | `GET /customers/?salesman=` |

- 列表统一支持分页 `?page=&page_size=`、搜索 `?search=`、筛选（`?category=`、`?salesman=`）；
- 响应统一格式：成功 `{code:0, message:"success", data:{...}}`，失败 `{code:错误码, message, data:null}`。

### 4.1 认证 API（JWT）

| 端点 | 功能 |
|---|---|
| `POST /api/auth/login/` | 用户名密码 → access + refresh token |
| `POST /api/auth/refresh/` | 刷新 token |
| `POST /api/auth/logout/` | 登出 |
| `GET /api/auth/me/` | 当前用户 + 角色 + 菜单权限 |

### 4.2 权限

- 4 个角色 = 4 个 Group：`admin`、`salesman`、`tracker`、`finance`；
- 自定义 `RolePermission`：基础信息模块内 admin 可读写，其余角色只读；
- 用户管理仅 admin；
- 数据可见范围（业务员看自己客户）留到订单模块。

## 5. 批量导入（产品库、工厂库）

流程：上传 Excel（multipart）→ `openpyxl` 解析 → 逐行校验 → upsert 入库 → 返回结果。

- **校验**：必填项、唯一性（product_no / 工厂 name）、外键（category 存在）；
- **幂等**：按 product_no / 工厂 name upsert，可重复导入；
- **模板下载**：标准 Excel 模板（表头 + 一行示例 + 填表说明）；
- **返回**：`{success_count, fail_count, failures:[{row, reason}]}`；
- **预览**：本期不做导入前预览，直接导入返回结果（预览为后续增强）。

## 6. 错误处理

统一异常处理器捕获 DRF/Django 异常，转统一响应格式。

| 场景 | HTTP | code |
|---|---|---|
| 校验错误 | 400 | 1001 |
| 未登录/token 过期 | 401 | 1002 |
| 无权限 | 403 | 1003 |
| 资源不存在 | 404 | 1004 |
| 导入部分失败 | 200 | 0（data 含 success/fail 计数） |

## 7. 前端设计

### 7.1 PC 端页面（Element Plus）

主布局：左侧菜单 + 顶部导航 + 内容区。

| 页面 | 内容 |
|---|---|
| 登录页 | 用户名密码登录 |
| 主布局 | 菜单 + 导航 + 面包屑 + 内容区 |
| 类目管理 | 两级树形展示 + 增删改 + 排序 |
| 产品库管理 | 表格 + 搜索 + 按类目筛选 + 新增/编辑抽屉 + 批量导入 |
| 工厂库管理 | 表格 + 新增/编辑 + 批量导入 + 别名维护 |
| 物流服务商管理 | 表格 + 新增/编辑（国内/国际分类） |
| 客户管理 | 表格 + 按业务员筛选 + 新增/编辑（归属业务员） |
| 用户管理 | 账号 CRUD + 角色分配 |

### 7.2 按端路由分流

| 路由 | 端 | UI 库 | 内容 |
|---|---|---|---|
| `/*` | PC/平板 | Element Plus | 基础信息全部功能（读写） |
| `/m/*` | 手机 | Vant | 登录 + 首页 + 基础信息只读浏览 |

- 按 `/m/` 前缀加载移动端布局与 Vant 页面，与 PC 路由隔离，两套 UI 库不混用、按需引入；
- 移动端本模块范围：登录 + 首页骨架 + 基础信息（产品库/工厂库/客户）只读列表；录入随业务模块补全；
- 路由守卫登录校验，Pinia 存 token/角色/权限，axios 拦截器注入 token、处理错误码。

### 7.3 前端技术栈

Vue3 + Vite + TypeScript + Vue Router + Pinia + axios；Element Plus / Vant 按需引入；接口定义集中在 `src/api/`。

## 8. 测试策略（TDD）

**后端**：`pytest + pytest-django + factory_boy`
- 模型测试：字段、唯一性、关系；
- API 测试：CRUD、分页/搜索/筛选、权限（各角色）、批量导入校验与 upsert；
- 认证测试：登录、token 刷新、me；
- TDD：先写测试再实现。

**前端**：`Vitest + @vue/test-utils`
- stores（user/权限）、api 封装、关键组件（列表、导入）测试；
- E2E（Playwright）本期不做。

**通过标准**：后端 `pytest` 全绿、前端 `vitest` 全绿。

## 10. 风险与备注

| 风险 | 应对 |
|---|---|
| Python 3.13 与部分库兼容性 | 选 Django 5.1+，锁定经测试的版本写入 requirements |
