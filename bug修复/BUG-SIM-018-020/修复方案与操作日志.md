# BUG-SIM-018/019/020 修复方案与操作日志 · 安全认证批

- 日期：2026-10-10 ｜ 基线：dev `ae044d5` ｜ 分支：`feature/bug-sim-018-020-auth-security`
- 决策（grilling 确认）：Q1:a 缓存计数限流（按 IP，5 次失败锁 10 分钟）；Q2:a access 8h→30min + 前端真正调 logout API；Q3:a 密码≥8 位且含字母数字（validate_password 全改密路径）；Q4:a 存量弱密码只标记不强制
- 用户附加指令：所有存量用户密码经一次性脚本统一重置为 `aa1234`（过渡态，不满足新规则，脚本写入不受校验；下次任何改密须合规）
- 连带补充：新加"个人改密"接口（/auth/me/change-password/，验旧密码+新规则），让用户能自行从 aa1234 升级到合规密码

## 实现

1. **018**：`LoginView` 按 IP 缓存计数——`login_fail:{ip}` 5 分钟窗口 5 次失败 → `login_lock:{ip}` 锁 10 分钟返回 429；成功登录清零计数。零新依赖（django.core.cache）
2. **019**：`SIMPLE_JWT.ACCESS_TOKEN_LIFETIME` 8h→30min（refresh 7 天不变，在线续命）；前端 NavRail 退出调 `logoutApi(refreshToken)`（blacklist refresh）再清本地——refresh token 需存 sessionStorage 供退出时提交
3. **020**：`UserManageSerializer` 与个人改密接口共用 `validate_password_policy(pwd)`（≥8 位 + 同时含字母与数字）；用户管理列表响应加 `is_weak_password` 只读标记（长度<8 或纯数字或纯字母——对照存量，aa1234 会被标记）
4. **个人改密**：`MeView` 加 POST action（旧密码校验 401、新密码走规则校验）
5. **数据脚本**：一次性 `management command reset_all_passwords --password aa1234`（直 set_password 不走校验，审计留操作日志）；运行后即弃

## 测试（TDD 先红）

- 018：同 IP 5 次错误密码 → 第 6 次 429；正确密码在锁定窗口内也 429；窗口过后恢复；成功登录清零
- 019：配置断言（ACCESS_TOKEN_LIFETIME=30min）；前端 logout 调 API（vitest mock 断言 logoutApi 被调用）
- 020：建用户弱密码 400（"1"/纯数字 8 位/纯字母 8 位）；合规密码 201；改密同规则；个人改密：旧密码错 401/对 200 且新密码生效/新密码弱 400
- Q4：`is_weak_password` 标记断言（aa1234 → True；合规 → False）
- 脚本：命令运行后所有用户 check_password('aa1234') 为真

## 边界

- 按 IP 限流对 NAT 共网用户可能误伤（内部系统可接受；生产可换 Redis 后端不改代码）
- logout 后旧 access 最长 30 分钟自然死（纯 JWT 无法即刻杀 access，业界折中）
- `aa1234` 重置后全员弱密码标记——预期行为，团队自行改密升级后自然消失
