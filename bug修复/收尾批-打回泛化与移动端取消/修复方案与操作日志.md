# 收尾批修复方案与操作日志 · FP/FPRecord 打回泛化 + 移动端取消入口

- 日期：2026-10-17 ｜ 基线：dev `48bca11` ｜ 分支：`feature/followup-recoil-mcancel`
- 来源：两批遗留待办清账（024 打回泛化至结算域；027 移动端取消入口记录在案项）
- 决策（grilling 确认）：
  - Q1:a FP/FPRecord 打回规则照搬 BUG-SIM-024（Order 同款）：非 admin 编辑**已批准**结算单/付款记录 → `is_approved=False` + 重挂对应类型审批（settlement/payment）
  - Q2:a 移动端取消入口放 MOrderDetail 底部操作栏（不放列表行）；可见性与确认形态照搬 PC 027：仅 admin + 未取消 + 二次确认

## 实现

1. **FP 打回**：`FactoryPaymentViewSet.perform_update`——`serializer.save()` 后，非 admin 且 `is_approved` → 置 False + 建 `settlement` AR + `resubmit_on_update`（判重跳过）；三步包 `transaction.atomic`
2. **FPRecord 打回**：`FactoryPaymentRecordViewSet.perform_update` 事务内——同规则打回 + 建 `payment` AR。**父单重聚合零额外代码**：`Record.save()` 无条件聚合且 `filter(is_approved=True)`，打回置 False 的 save 触发重聚合，已付自动减去编辑中的付款（"未批准 = 不产生业务效果"口径闭环）
3. **下游自动生效**（无改动）：打回的 FP 从对账单消失（statement 已滤 is_approved=True）；打回的 FPRecord 不计入已付；approve 侧映射已含 FactoryPayment/FactoryPaymentRecord（005 批实现，批准后持父单行锁重算）
4. **移动端**：MOrderDetail 底部操作栏加"取消订单"按钮（`isAdmin && !order.is_cancelled`，warning 色）→ `showConfirmDialog` 二次确认（文案同 PC：冻结新增结算/付款、存量保留）→ `PATCH is_cancelled: true` → toast + 重载详情（状态 tag 变"已取消"）

## 边界

- 打回仅影响"编辑已批准"路径；未批准单编辑仍走既有 `resubmit_on_update`（刷新既有 AR）
- 打回记录仍占超付预算（_check_overpay 统计全部记录含待审，BUG-SIM-006 口径不变）
- 打回的 FP 期间工厂汇总/对账单不含它，批准后恢复——管理员视角审批列表可见全部 pending
