# Logistics 打回泛化与锁加固批方案与操作日志

- 日期：2026-10-18 ｜ 基线：dev `00af5f0` ｜ 分支：`feature/logistics-recoil-lock`
- 来源：锁加固批审查 note——Logistics 从未纳入 024 打回口径（024 只泛化 Order、收尾批只泛化 FP/FPRecord）；经用户确认泛化（审批域四模型口径闭环）
- 决策：规则与 Order 024 / FP/FPRecord 完全同构——非 admin（tracker 是唯一非 admin 写权角色）编辑**已批准**发货单 → `is_approved=False` + 重挂 `logistics` 审批 + Logistics 行锁重读（`serializer.instance` 重绑防快照覆盖，锁加固批同口径）；admin 不受影响。本批唯一决策已由用户上轮批准，无新分叉，未重复 grilling

## 事实核查（实现前）

- `Logistics.is_approved` 存在、serializer read_only（models.py:28 / serializers.py:17）
- approve 侧 `TARGET_APP_MODEL` 已含 Logistics（system_mgmt/views.py:24），approve target 行锁已就位（锁加固批），锁序编辑=target 单锁与 approve=AR→target 一致无死锁
- **下游自动闭环**：收支流水物流费用源已滤 `is_approved=True`（finance/views.py:175，BUG-SIM-005 批实现）——打回的发货单费用自动从流水消失，approve 后恢复，零额外改动

## 实现

`LogisticsViewSet.perform_update`：atomic 内 `select_for_update` 锁行重读 + `serializer.instance = locked` + save + 打回分支（approval_type='logistics'）+ resubmit_on_update（既有语义保持）

## 测试（TDD 先红）

- tracker 编辑已批准发货单 → 200 + 打回 + pending `logistics` AR（tracker_client 返回 (client, user) 元组，order.tracker 先指派自己）
- admin 编辑已批准发货单 → 不打回、无新 AR
- 全量回归：流水排除/审批门禁等既有行为零破坏

## 边界

- update 路径无 tracker 归属对象校验（既有现状，get_queryset 已限可见范围）——本批不扩
- 打回的发货单期间流水不含其费用，批准后恢复（与 FP/FPRecord 口径一致）
