- 日期：2026-09-15 ｜ 基线：dev `de60ae5` ｜ 分支：`feature/bug-sim-002-settlement-guard`（自 dev 拉出，完成后合并回 dev）

## 1. 问题描述

订单明细采用"整组替换"式更新，三条路径全部实锤静默清空结算数据：

| 路径 | 触发 | 后果 |
|---|---|---|
| ① 导入 | 已有结算+付款的订单重导 Excel | `importers.py` 删全部 items → 结算单+付款记录 CASCADE 消失 |
| ② UI 改价 | 编辑页正常改单价保存 | 毛利重算正确，但已结结算单+付款记录被删 |
| ③ UI 仅改状态 | 编辑页只改跟踪状态保存 | 与金额无关的改动也触发全删（前端保存必带 items） |

根因：`orders/serializers.py:47-57` update 对 items 全删重建；`orders/importers.py:129` 重导整组替换；`factory_payment/models.py:8` FactoryPayment OneToOne(OrderItem, CASCADE)，Record 二级 CASCADE。

## 3. 修复设计

### 3.1 保护核心（共用守卫函数，orders app 内）

```python
# orders/services.py（新建）
SETTLEMENT_FROZEN_FIELDS = {'qty', 'unit_price', 'subtotal', 'cost_price'}

def get_settled_items(order) -> dict[item_id, FactoryPayment]:
    """item_id -> 其挂着的结算单（存在即算，不论未结/部分结/已结）"""

def ensure_order_deletable(order):
    """Q5:i —— 订单任一明细挂结算 → 抛 ValidationError('订单已挂结算单/付款记录，禁止删除...')"""

def check_items_diff(order, incoming) -> None:
    """Q1:A + Q2:i —— 三类拦截，ValidationError 汇总报出全部冲突行：
    1. 被删除的行挂结算 → '明细(产品 X)已挂结算单，不可删除'
    2. 原位更新的行是结算行且改了金额字段 → '明细(产品 X)已挂结算，金额字段冻结'
    （新建行无结算概念，不检查）"""
```

### 3.2 UI diff（`orders/serializers.py::OrderSerializer.update`）

- `items` 带原 `id` 且 id 属于该订单 → 原位 update（先跑 `check_items_diff` 拦截）
- 无 id（或 id 为空）→ create
- DB 有而 payload 没有 → delete 前先过保护检查（任一冲突 → **整单 400**，报全部冲突行，不落任何写入）
- 整个 update 包 `transaction.atomic`（校验失败=零写入）
- `calc_order_profit` 照旧在写后执行

### 3.3 前端（`OrderForm.vue`）

- 加载时保留 `it.id`，提交 payload 的 items 带 `id`（新加行无 id）——约 2 行
- 400 错误经既有全局 toast 展示后端给出的冲突原因

### 3.4 导入 diff（`orders/importers.py`）

对已存在订单（不再 `items.all().delete()` 整组替换）：

1. **归属校验（Q7:i）**：订单不在操作者数据范围内（admin/finance 全部；salesman 自己客户；tracker 派给自己）→ 整单失败"无权限更新该订单"
2. **匹配键（Q6:b）**：按订单内 `product_no` 匹配：
   - Excel 行 product_no 命中唯一已有明细 → 原位更新（行 id 不变，结算保持）
   - 未命中 → 新建
   - 已有明细的 product_no 在 Excel 中缺席 → 视为删除 → 过保护检查
   - **安全失败规则**：同一订单内 Excel 出现重复 product_no、或已有明细存在重复 product_no、或待更新行 product_no 为空 → 整单失败"产品编号重复/为空，无法安全更新"（宁可拒绝不可错账）
3. 新建订单流程完全不变（无匹配概念）
4. 订单级失败进既有 failures 清单（带 row+reason），同批其他订单照常导入

### 3.5 删除保护（Q5:i）

- `OrderViewSet.perform_destroy` 先 `ensure_order_deletable(order)` → 400
- `bulk_delete` 循环内对每个订单先跑守卫 → 冲突的进 forbidden 清单不删（复用 BUG-SIM-001 的报告机制）；`ensure_order_deletable` 的 ValidationError 在 bulk 循环里转为 forbidden 条目
- 结算数据被保护后，admin 删单流程：先删结算单（现有 admin-only 权限）→ 再删订单

## 6. 边界与风险

- **003 仍开放**：导入更新仍会覆写 tracking_status（状态机旁路）、已批准订单不重挂审——本次范围外，已有归属校验兜底跨归属越权
- **重复 product_no 历史数据**：现存订单若已有重复 product_no 明细，重导会安全失败（提示走编辑页）——不静默处理
- **删除体验变化**：admin 删挂结算订单需先删结算单，属修复目标本身（Q5:i 明确选择）
- **导入 Excel 不带明细 id**：靠 product_no 匹配（Q6:b 用户选定），行序调整不再影响匹配——这是 b 相对 a（seq）的取舍收益
