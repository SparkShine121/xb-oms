- 决策（grilling 确认）：
  - Q1:a #5 三管齐下——①登录成功回调 `ElMessage.closeAll()` 清残留（核实：toast 均 EP 默认 3s，"跨登录残留"是 3s 窗口内成功后旧错误仍在的观感）；②登录失败与全局请求错误 ElMessage 加 `grouping: true`（相同内容合并带计数，消除堆叠）；③"保存/审批后弹窗不自动关闭"子项先实测复验（现状代码已变：OrderForm 保存 3s 跳转、审批为模态确认框），复现再修
  - Q2:a #8a **12 处**禁用控件加原生 `title`：批量删除×7="请先勾选要删除的行"、批量导入×3="请先选择 Excel 文件"、订单号（编辑锁定）×2="订单号创建后不可修改"、跟单员下拉×1="仅管理员可修改"；CategoryManage 下拉选项禁用（防选自身）语义自明跳过；MOrderForm 两处（订单号/业务员）经审查证伪后**删除**——Vant 的 `van-field` 有声明 `title` prop（Cell 共享），传值被静默吞不进 DOM，且移动端触屏本无 hover
  - Q3:a #8b 预览实测复验：删除后代码本就有 load() 全量刷新，错乱疑为瞬态——稳定复现才定位修，不复现记录关闭

## 实现

1. **Login.vue**：失败 ElMessage 加 grouping；成功回调先 closeAll（成功后旧错误无意义）
2. **request.ts**：全局错误 `ElMessage.error(...)` 改配置对象形式带 `grouping: true`（相同错误消息全局合并）
3. **title 透传**：FactoryManage/LogisticsManage/CustomerManage/ProductManage/OrderList/LogisticsList/FactoryPaymentList 的批量按钮 + OrderForm 订单号/跟单员 + MOrderForm 订单号/业务员
4. 前端零后端改动；vitest 全量 + build 门禁；预览实测四项（toast grouping/closeAll、title 透传、tag 复验、弹窗复验）

## 边界

- grouping 合并的是"相同内容"消息——不同错误仍各自出现（合理：不同原因不该被合并吞掉）
- title 为 PC hover 提示；移动端触屏无效但加之无害（MOrderForm 两处顺带）
- closeAll 仅登录成功时触发（时机唯一，不影响业务页 toast）
